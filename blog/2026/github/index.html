GitHub Traffic Tracker (>14 days)

Created on May 05, 2026

2026

Problem Statement: GitHub provides access to only the past 14 days of repository traffic data. Existing solutions are not simple and are not designed for the specific output I want.

Solution: A simple algorithm can track daily and cumulative counts for total and unique repository views and clones.

Note: The traffic tracker tracks a single repo. For each repo you need to create a new tracker.

How to do it:

  1. GitHub Personal Access Token (PAT):

Go to Settings > Developer Settings > Tokens (classic). Create a token with the repo scope (Permission: Metadata and Administration - Read only)

Save the Token ! We will use it.

  1. Google Service Account for JSON key:

Go to the Google Cloud Console.

Enable the Google Drive API (Click on the navigation menu on the top left corner -Hamburger icon-, then select API & Services > Enable API & Services).

Create a project, Name your project, Select the organization (I selected No organization)

Now on the search bar (top menubar) search for “Google Drive API” and click on it. Then Enable the API.

Click on the Hamburger icon again and select IAM & Admin > Service Accounts + Create Service Account

Type “Service Account Name” which would be username for your email. + Create and continue

Permissions: Basic > Editor + Done

Click on the hyperlink of the email you just created. Click on Keys on the top menu bar (Details, Permissions, Keys, …)

Generate a JSON Key, and download it: Add key. Create a new Key. Key type: Json

  1. Google driver to create *.csv file:

Open your Google Drive in your browser.

Create or select the folder where you want the CSVs to live.

Open the .json file you just downloaded and copy the “client_email” value (it looks like name@project-id.iam.gserviceaccount.com).

Share the Google Drive folder with that email address, giving it Editor permissions.

Create a csv file (e.g., traffic states.csv) and save the “1sdsN3bo-kX8dsdsrawMI” part in the hyperlink where we will use it in the “get_traffic.py” script. The link should look like something like this:

https://docs.google.com/spreadsheets/d/1sdsN3bo-kX8dsdsrawMI/edit?gid=22392112#gid=22392112

  1. Back to your github account to create get_traffic.py and daily_traffic.yml:

Click on the repo that you want to track the traffic.

Create a file name “get_traffic.py” at main (not within a folder).

Paste the python code with changes:

a) The REPO line

Change this to the actual path of your repository.

Example: REPO = “JohnDoe/WeatherApp”

b) The FILE_ID line

Change this to the ID of the Google Drive csv file where you want the files saved (Explained on the at the end of the 3rd step)

Create a folder name: .github/workflows

Create a file under this folder: daily_traffic.yml

Configure your GitHub “Secrets”:

In your GitHub repo, go to Settings (top tab) > Secrets and variables (left sidebar) > Actions.

Click New repository secret for each of these:

Name: GH_TOKEN (Paste your GitHub Personal Access Token).

Name: GDRIVE_JSON (Open your Google Service Account JSON file, copy the entire text inside it, and paste it here).

  1. Launch the Test

Go to the Actions tab at the top of your GitHub repo.

Click Daily Traffic Sync (or whatever you named the workflow) on the left sidebar.

Look for a gray bar that says “This workflow has a workflow_dispatch event trigger.”

Click Run workflow -> Run workflow (green button).

Check your csv file if it is writte.

Ta Da ! It is over. Now you can track your GitHub Repo.
